# Outfit “晨间试衣台”全前端重构设计

## 背景与模式判定

Outfit 是面向单个用户的本地优先衣橱决策应用。核心闭环是：

`淘宝采集/导入 -> 衣物确认 -> 天气与个人画像 -> 今日推荐 -> 标记已穿 -> 历史洞察`

2026-07-07 的“安静高级工作台”演进已经统一过冷灰绿 token、卡片层级和局部响应式，但 2026-07-08 的真实截图仍表现为卡片化后台。用户再次明确评价现有前端“真的很丑”，因此本轮判定为 **Redesign - Overhaul**：保留业务能力、信息架构、接口契约和中文语义，全面重做视觉语言、页面构图、状态层级和组件组织。

## 设计读取

Reading this as: 面向单个高频用户的本地优先衣橱决策产品，以图像优先、冷静克制的“晨间试衣台”为语言，基于 React、Tailwind v4 和项目自有无样式组件重构。

- `DESIGN_VARIANCE: 6`：今日推荐和洞察有目的地非对称，维护页保持秩序。
- `MOTION_INTENSITY: 4`：只为结果生成、抽屉、选择和反馈增加过渡。
- `VISUAL_DENSITY: 5`：日常页降低同时可见信息，审核队列局部保持 6。

## 产品原则

1. 用户每天最先需要回答“今天穿什么”，推荐页必须是首要体验。
2. 真实本地衣物图是产品的动态品牌资产，不使用生成的假截图或无关图库照片。
3. 日常决策、衣橱浏览、数据维护和系统维护使用不同密度，不再共享同一种工作台卡片语法。
4. 默认用留白、对齐和稀疏分隔线组织信息，仅推荐结果、弹窗和可选择项使用明显表面。
5. 青绿色是唯一品牌强调色；蓝、黄、红只承担信息、警告和危险语义。
6. 本地隐私不是技术脚注，而是认证、导入和模型界面的明确价值说明。

## 视觉系统

### 色彩

亮色基础：

- Canvas `#f3f5f4`
- Surface `#fcfdfc`
- Surface muted `#edf1ef`
- Ink `#17201e`
- Muted `#66716d`
- Line `#d8dedb`
- Accent `#0f766e`
- Accent strong `#0b5c56`
- Navigation `#111817`

暗色通过同一组语义变量在 `prefers-color-scheme: dark` 下映射，不在页面内部翻转主题。主按钮使用实色，不使用渐变和外发光。

### 字体与数字

字体栈：`"Segoe UI Variable", "PingFang SC", "Microsoft YaHei UI", system-ui, sans-serif`。英文与数字继承同一栈，统计数字使用 `font-variant-numeric: tabular-nums`。标题依靠字重、行高和空间建立层级，不使用营销页式超大字号。

### 形状与层级

- 页面表面：14px。
- 控件：10px。
- 状态、分段选择：可使用全圆角。
- 阴影只用于弹窗、悬浮导航和主推荐结果；普通分组依赖背景、边界和留白。
- 图标继续使用项目现有 Lucide，统一线宽与 16/18/20/24 尺寸层级。

### 动效

- 只动画 `transform` 与 `opacity`。
- 页面切换做轻量淡入，推荐结果按信息层级进入。
- 按钮 active 轻微缩放，抽屉和 dialog 使用状态过渡。
- `prefers-reduced-motion: reduce` 下全部取消位移和自动动画。

## 架构边界

目标结构：

```text
src/
  app/                 应用壳、认证门禁、导航与编排
  features/
    auth/
    recommendations/
    wardrobe/
    import/
    insights/
    settings/
  components/ui/       Button、Field、Dialog、Badge、Surface、EmptyState 等
  shared/              既有 types.ts + labels/defaults
  lib/                 图片、筛选、存储、下载等纯函数
  styles/              tokens、globals、components、responsive
```

兼容策略：

- `src/App.tsx` 保留为应用入口及既有测试符号重导出。
- `src/api.ts` 本轮保持原路径和行为，不扩大为 API 重写。
- `src/shared/types.ts` 保持原路径，因为服务器直接引用。
- 五个主导航标签和 tab 值保持不变，不新增 URL 路由。
- 先拆展示组件与纯函数，再迁移业务状态，确保每一步都可测试。

## 页面蓝图

### 今日推荐

- 桌面使用约 38/62 非对称布局：左侧为当天摘要、场合选择和一个条件化主动作；右侧是首选搭配舞台。
- 不在首屏展示原始经纬度，只显示天气摘要；位置细节放入设置。
- 首选搭配用更大衣物抠图组成视觉组合，替代方案降级为紧凑列表。
- 空态只给一个下一步：无衣物则导入，信息齐备则生成，不重复同意图按钮。

### 衣服库

- 页头提供“全部 / 待确认”视图模式，待确认数量是可行动信息。
- 已确认衣橱使用图像优先网格；待确认使用高效审核行。
- 筛选器使用有标签的可折叠工具栏；只有产生选择时才显示批量条。
- 每件衣物默认只展示图片、名称、关键属性和主状态；编辑、视觉处理和危险操作进入详情区域。

### 历史洞察

- 首屏回答三个问题：衣橱健康如何、使用是否均衡、下一件最值得补什么。
- 健康度成为主诊断，分布使用真实的比例可视化而不是 chip 墙。
- 洞察、购物和身材建议按优先级形成叙事；原始推荐时间转为本地可读格式。
- 次要分布和推荐历史可以渐进披露。

### 导入

- 浏览器采集是单一主入口；订单采集与商品详情采集清晰分支。
- 采集状态使用步骤/状态轨迹表达，PID、输出目录和原始 JSON 下沉到高级详情。
- 书签脚本保留但降为替代方式；预览突出将新增、重复、过滤和需人工确认。

### 设置

- 分为位置、个人偏好、本地视觉三块；每块使用明确字段关联和说明。
- 模型路径、底层错误与技术细节放入可展开区域。
- 保存与定位反馈使用 `role="status"`，错误就近显示。

### 认证与弹窗

- 认证保留单一聚焦表单，并明确“衣橱与购买数据保存在本机”。
- 缩略图选择改为原生 `<dialog>`：支持 Escape、焦点恢复和浏览器焦点管理；移动端呈底部 sheet。

## 响应式

- 桌面导航为紧凑侧栏，内容宽度与页面任务匹配，不让侧栏主导空页面。
- 小屏采用页面自然滚动，不使用固定高度 workspace 内部滚动。
- 移动导航保留可见文字；五项导航可在 10-11px 标签下排列，退出移入账户区域。
- 320px 下筛选器和表单回到单列；关键动作不重叠、不被底栏遮挡。

## 状态与可访问性

- 首次加载与真实空态分离，使用同形骨架或明确加载区域。
- 全局系统故障使用 `role="alert"`；成功、复制、已穿等反馈使用 `role="status"`。
- 每个输入、select、checkbox 都有可见 label 或可访问名称。
- 导航保留 `aria-current`，分段选择与候选图保留 `aria-pressed`。
- 图片保留本地优先、可信淘宝 CDN、`no-referrer`、lazy、async decoding 和错误占位契约。
- 关键文本和控件达到 WCAG AA；主按钮不再使用对比度不足的浅端渐变。

## 不在本轮扩大范围的事项

- 不修改后端、数据库 schema、推荐算法或 API 路由。
- 不改变衣物逐字段提交语义，不实现采集/模型任务轮询重构。
- 不删除本地数据、截图、缩略图、模型、日志或浏览器登录态。
- 不引入营销图片、玻璃拟态、复杂滚动动画或新的图标体系。

## 验收

- 今日、衣橱、洞察三页有清晰不同的任务构图，不再是同形卡片堆叠。
- 导入和设置技术细节得到渐进披露。
- 桌面与 390px/320px 移动视口无重叠、遮挡、溢出或不可识别导航。
- 亮暗主题 token、焦点、reduced motion、加载/空/错/成功状态可用。
- 类型检查、目标测试、完整测试、生产构建和真实浏览器 QA 全部通过。
