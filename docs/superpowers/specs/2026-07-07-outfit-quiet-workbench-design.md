# Outfit 安静高级工作台重构设计

## 背景

Outfit 是一个本地优先的穿搭管理与推荐工具。它从淘宝订单页或商品详情页采集服饰候选，导入本机 SQLite 衣橱库，再结合天气、场合、最近穿着记录和本地视觉能力生成可解释的搭配建议。

当前前端已经具备完整业务能力，但页面观感偏“浅色后台表单”：白色卡片、浅边框、浅灰按钮和重复面板过多，推荐页、衣橱页、历史洞察页缺少清晰的主次节奏。用户希望页面看起来更高级，不再死气沉沉。

本次设计采用用户已确认的 A 方向：“安静高级工作台”。这不是营销页重做，也不是时装杂志化改造，而是在保留高频工具效率的前提下，提升信息层级、视觉节奏、材质克制和交互反馈。

## 设计读取

Reading this as: local wardrobe product workbench for a single user managing outfits frequently, with a quiet premium utility language, leaning toward existing React + Tailwind v4 + custom design tokens.

设计拨盘：

- `DESIGN_VARIANCE: 5`。需要比现状更有层级和节奏，但不做实验性布局。
- `MOTION_INTENSITY: 3`。以 hover、active、focus 和轻量过渡为主，不引入滚动叙事或复杂动画。
- `VISUAL_DENSITY: 6`。保留工作台扫描效率，避免营销页式留白。

设计系统选择：

- 继续使用现有 React、Vite、Tailwind v4、DaisyUI 和自定义 CSS token。
- 不新增大型组件库。
- 继续使用项目已有 `lucide-react` 图标，避免一次视觉重构同时更换图标体系。

## 现状审计

### 品牌与视觉 token

- 现有主色为青绿色 `#0f766e`，辅色为蓝色 `#2563eb`。
- 背景叠加了青绿、蓝、白、暖米和粉色渐变，颜色气质不够锁定。
- 圆角基本统一为 8px，移动端底部导航使用胶囊形，这是合理的交互例外。
- 字体为 `Inter, "Segoe UI", "Microsoft YaHei", system-ui, sans-serif`，适合工具型界面，第一版不更换。

### 信息架构

主导航保持不变：

- 今日推荐
- 衣服库
- 历史洞察
- 导入
- 设置

页面切换仍由当前 `MainApp` tab 状态控制，不引入路由。

### 内容块

- `RecommendationView` 是默认首页，应成为最有设计感和决策感的页面。
- `WardrobeView` 是高频管理页，应强调扫描、筛选和局部编辑，而不是所有字段平均展示。
- `HistoryInsightsView` 目前由多个重复二维卡片组成，应改成总览、诊断、建议的层级。
- `ImportView` 已有采集、检查、导入流程，应压低高级 JSON 区域的视觉优先级。
- `SettingsView` 是工具配置页，保持清楚、稳定、低干扰。

### 需要退休的模式

- 多层彩色渐变背景造成的柔软和漂浮感。
- 每个区域都用卡片和阴影包住，导致层级平均。
- 状态标签、筛选 chip、按钮共享太多 hover 行为，语义不够清晰。
- 移动端使用 `100vh` 和固定高度计算，存在浏览器地址栏导致的跳动风险。
- 衣橱行默认呈现为大表单，业务能力强但视觉负担重。

### 需要保留的模式

- 深色侧边栏和青绿色品牌记忆。
- 页面 tab、导航标签和核心操作文案。
- 本地隐私边界、删除确认、导入安全提示和数据备份文案。
- 已有可访问性基础：按钮 aria label、焦点轮廓、图片 alt、移动端紧凑导航。

## 目标

- 让默认首页“今日推荐”像一个有判断力的穿搭决策面板，而不是按钮和卡片的堆叠。
- 让“衣服库”从表单堆叠变成可扫描的专业衣橱库，同时保留所有编辑能力。
- 让“历史洞察”从重复卡片变成结构化诊断页。
- 统一色彩：青绿色作为唯一品牌主色，蓝色仅用于链接或信息态，移除粉色和暖米背景噪音。
- 减少无意义阴影：重要浮层和关键推荐卡保留阴影，普通行与分组更多依赖边框、留白和密度。
- 提升移动端稳定性：使用 `100dvh`，底部导航不遮挡关键内容。
- 保留当前功能、数据流、API、删除确认和本地优先安全边界。

## 非目标

- 不重写推荐算法。
- 不修改 API 路由、数据库 schema 或服务端业务逻辑。
- 不改变主导航标签、页面顺序或 tab 结构。
- 不删除本地数据、采集产物、缩略图、日志或登录态。
- 不进行大规模文件拆分。组件抽象只服务本次视觉重构。
- 不重新引入此前已移除的 liquid glass 滤镜、SVG 位移滤镜或全局玻璃体系。

## 视觉语言

### 主题

采用单一浅色主题，带深色侧边栏。页面不做 section 级明暗切换。

推荐 token 方向：

- 画布：冷灰白或轻微青灰。
- 主表面：白色或接近白色。
- 抬升表面：更少、更明确，只用于推荐卡、弹窗和关键面板。
- 主色：青绿色。
- 辅助信息色：低饱和蓝色，仅用于链接、信息提示或天气类信息。
- 状态色：成功、警告、危险保留，但降低面积和饱和度。

### 字体

继续使用现有 sans 字体栈。视觉提升主要来自：

- 标题层级更明确。
- 数字和状态更稳定。
- 描述文本减少冗余。
- 面板标题、按钮、标签的字重更有区分。

### 形状

- 主体圆角保持 8px 到 10px。
- 移动端底部导航和分段控件允许胶囊形。
- 不混用大圆角卡片、锐角面板和胶囊按钮。规则是：工具表面 10px，按钮 8px，移动导航胶囊。

### 动效

- 不新增复杂动画库。
- 使用 CSS transition 做 hover、active、focus 和选中态反馈。
- 状态标签不做 hover 抬升，只有真正可点击控件才有触感反馈。
- `prefers-reduced-motion: reduce` 下禁用位移类动效。

## 组件设计

### `src/components/workbench.tsx`

现有组件继续保留，并扩展为更有语义的工作台基础件：

- `PageHeader` 增加 `variant` 或 className 约定，支持默认页头和推荐页重点页头。
- `StatTile` 保持，但样式区分普通统计和关键统计。
- `CommandBar` 继续作为操作条，样式更扁平，更像工具栏。
- `WorkbenchPanel` 支持更清晰的密度和层级 class，例如普通面板、重点面板、无阴影面板。
- 新增或约定 `SurfaceSection`、`SummaryStrip`、`EmptyState` 这类语义容器时，只做轻量封装，不迁移业务逻辑。

组件扩展的目标是减少页面里散落的局部样式 class，而不是建立新的完整设计系统。

## 页面设计

### 今日推荐

页面目标：默认首页应该回答“今天穿什么”。

结构调整：

1. 顶部页头保留标题、描述和坐标/可用衣物/当前场合统计。
2. 场合切换与天气/生成按钮整合成更明确的决策工具栏。
3. 天气上下文从大块浅青提示条改为紧凑 context band。
4. 推荐卡片强化主视觉层级：
   - 匹配度放在固定角落，不拉伸。
   - 单品预览使用更稳定的两层或多层 outfit stack。
   - 理由只展示前 2 条，更多理由和替代单品继续折叠。
   - “标记已穿”作为明确的次要完成动作。
5. 空态保持可操作，提示先获取天气或生成推荐。

不改变：

- `onOccasion`
- `onFetchWeather`
- `onGenerate`
- `onRecordWearLog`
- 推荐结果数据结构

### 衣服库

页面目标：快速扫描、筛选、批量确认和局部编辑。

结构调整：

1. 页头保留总件数、待确认和显示件数，但统计 tile 更轻。
2. 筛选条更像搜索和过滤工具条，减少卡片感。
3. 批量操作条只在有结果时形成清楚层级，按钮对齐更稳定。
4. 衣物行改为“信息区、属性区、动作区”三段：
   - 信息区突出缩略图、品牌、名称和确认状态。
   - 属性区保留类别、颜色、保暖、尺码、材质、图案、标签、季节。
   - 动作区收敛为统一网格，避免按钮看起来像随机堆叠。
5. 视觉建议作为辅助块，降低默认噪音。
6. 空态和筛选无结果状态保持明确。

不改变：

- 选择、批量确认、更新、删除、去背景、视觉分析、缩略图选择的行为。
- 删除仍走 `confirmDelete()`，不绕过用户确认。

### 历史洞察

页面目标：从“很多统计卡片”变成“衣橱诊断”。

结构调整：

1. 顶部用健康度、活跃衣物、未穿衣物等关键指标形成总览。
2. 颜色、类别、季节、场合分布使用更紧凑的分布块。
3. 建议分为洞察建议、购物建议、身材建议，优先级标签更语义化。
4. 推荐历史作为附属信息，不与诊断内容抢视觉重心。

不改变：

- `WardrobeInsights` 数据结构。
- 历史数据读取和错误处理。

### 导入

页面目标：保持采集流程清楚，但减少工具堆叠感。

结构调整：

1. 三步流程保留，但视觉从浅绿块改为更克制的 step strip。
2. Selenium/Playwright 采集区作为主流程面板。
3. 书签脚本和 JSON 高级导入保持，但 JSON 区域不抢主流程优先级。
4. 预览结果保持 metric strip 和候选列表，样式统一到新 token。

不改变：

- 采集任务、读取产物、预览、导入行为。
- 淘宝链接、书签脚本和 JSON 文本框。

### 设置

页面目标：低干扰配置页。

结构调整：

1. 设置面板使用相同表面 token。
2. 本地视觉模型状态更像配置表，而不是一组普通卡片。
3. 保存和定位按钮保持清晰。

不改变：

- 经纬度保存。
- 个人画像表单。
- 本地视觉开关、下载和验证行为。

## 数据流

本次重构不改变数据流：

- `MainApp` 仍负责加载衣物、个人画像、历史、模型状态、天气和推荐。
- 各 View 仍通过 props 接收数据和回调。
- API 函数、服务端、数据库和类型定义保持现有契约。
- 所有错误继续进入现有 `error` 状态或局部错误状态。
- 乐观更新、回滚、候选图加载和保存逻辑不改。

## 错误、加载和空态

需要保留并视觉统一：

- 认证加载卡片。
- 全局错误 banner。
- 导入预览错误。
- 衣橱读取失败。
- 推荐生成失败。
- 缩略图候选加载和保存错误。
- 没有衣物、筛选无结果、没有推荐、没有历史洞察、没有模型状态。

改造原则：

- 错误用明确文本和危险色，不用 toast 取代现有上下文。
- 加载中按钮文案保留，例如“生成中”“预览中”“保存中”。
- 空态不做大型插画，使用简洁说明和下一步操作。

## 可访问性与响应式

- 保留现有按钮文本、title、aria label 和图片 alt。
- 所有按钮保持足够对比度。
- 输入框 label 不用 placeholder 替代。
- 桌面导航不换行，高度保持在 80px 以下。
- 移动端底部导航使用 `100dvh` 相关高度，避免地址栏变化造成裁切。
- 关键操作按钮在 390px 宽度下不重叠。
- 文本使用 `overflow-wrap` 和稳定 grid，长品牌名、商品名、模型路径不撑破布局。

## 测试计划

自动验证：

```powershell
npm test
npm run typecheck
npm run build
```

视觉验证：

- 启动本地开发服务。
- 截图桌面和移动端的今日推荐页。
- 截图桌面和移动端的衣服库。
- 截图设置页。
- 截图缩略图弹窗。
- 检查导航、按钮、输入框、筛选条、衣物行、推荐卡、历史洞察面板是否有重叠或不可读文本。

设计自检：

- 色彩锁定：青绿色为唯一品牌主色。
- 页面主题锁定：不在页面中随机切换明暗主题。
- 形状锁定：工具表面和按钮圆角规则一致。
- 卡片克制：普通行减少阴影，关键面板才抬升。
- 状态语义：状态标签不表现得像按钮。
- 移动端稳定：使用 `100dvh` 替代关键 `100vh`。
- 不出现新的 decorative status dot、滚动提示、版本标签或无意义装饰文案。
- 不重新引入 liquid glass 相关 CSS、SVG 滤镜或 `backdrop-filter`。

## 风险

- 当前 `App.tsx` 是大型文件，视觉重构应保持小步修改，避免顺手做架构迁移。
- 测试里对 CSS 规则有较多断言，样式重构需要同步更新测试，不能只改视觉不改验证。
- 移动端底部导航容易遮挡内容，需要用真实截图确认。
- 衣橱行信息密度高，收敛视觉时不能隐藏用户高频编辑字段。
- `.superpowers/` 是视觉辅助工作目录，应被 Git 忽略，不作为产品产物提交。

## 验收标准

- 用户确认的 A 方向被落实为冷静、专业、可扫描的工作台视觉。
- 今日推荐、衣服库、历史洞察都有比现状更明确的主次层级。
- 导入和设置页与新 token 统一。
- 核心功能行为不回退。
- 自动测试、类型检查和构建通过。
- 桌面与移动端截图没有明显重叠、遮挡、按钮文字溢出或低对比问题。
